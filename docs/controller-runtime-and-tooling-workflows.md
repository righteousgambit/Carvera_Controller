# Runtime ergonomics and advanced tooling requirements

These 25 recommendations extend the existing nine ledgers under the active
implementation objective. They deepen shared foundations without replacing
prior requirements. Each remains OPEN until its complete applicable workflow
is demonstrated. Offline models do not establish machine execution support.

| # | Requirement | Required acceptance evidence |
|---|---|---|
| 1 | Universal entity search | Tools, fixtures, programs, operations, measurements, alarms and settings resolve to shared authoritative context |
| 2 | Value provenance | Source, time, revisions and effective governing values accessible from important fields |
| 3 | Type-dependent tool forms | Relevant cutter/drill/insert geometry fields and dimensional illustrations with correct validation |
| 4 | Execution mode workspace | Observed Auto/MDI/Jog state distinguished from Preview, available actions explained and dispatched through actual backend |
| 5 | Illustrated dimensions | Tool/setup/probe dimension selection highlights its exact definition in an applicable drawing |
| 6 | CAM output watching | Stable file changes identified, differences reviewed, active running program identity preserved |
| 7 | Cancellable calculations | Import/simulation/collision progress, cancellation, result input identities and change invalidation |
| 8 | View versus motion gestures | Scene inspection and intentional jog workflows remain distinct with frame/increment/destination feedback |
| 9 | Selective setup duplication | Explicit inherited tools/process/setup fields and replaced geometry/datum reviewed without hidden old offsets |
| 10 | Return-to-work briefing | Program/toolbank/fixture/drafts/measurement changes since last session with direct actionable navigation |
| 11 | Single-block rehearsal | Next-block motion/modal effects and preview step separated from actual supported single-block/optional-stop control |
| 12 | Block-delete alternatives | Actual dialect branches, resulting path/tool/operation changes and supported observed execution policy |
| 13 | Reviewed MDI scratchpad | Sequence path/state effects, reviewed supported execution and applicable modal restoration/readback |
| 14 | Parameter/expression inspector | Actual interpreter variables, evaluations, call stacks and selected-motion dependency trace |
| 15 | Learned completion estimates | Comparable observed cutting/travel/change/ramp/intervention timing, remaining range and provenance |
| 16 | Program efficiency map | Quantified travel/retract/dwell/change opportunities with reviewed changes and semantic preservation |
| 17 | Shared machine resources | Operation resource requirements, actual sensor feedback and machine-side permissives explain waits |
| 18 | Override ownership | Program/operator/adaptive/controller restrictions and actual enable/disable state explain effective controls |
| 19 | Configuration upgrade review | Firmware/configuration capability differences identify affected jobs and invalidated qualification evidence |
| 20 | Spindle gearbox visualization | Documented speed/torque ranges, required/observed gear and qualified transition requirements |
| 21 | Auxiliary U/V/W axes | Backend configured frames/limits/jog/path/simulation semantics beyond XYZABC |
| 22 | Spindle-to-C-axis transition | Actual orientation/mode/mechanism handshakes, machine-specific interlocks and live-tool sequence |
| 23 | Angle heads/aggregate tooling | Holder-to-cutting-axis transform, tip/direction/reach and collision geometry with actual applicability |
| 24 | Individual insert edges | Body/position/edge identity, edge use, indexing event, retained history and measurement requirements |
| 25 | Commanded versus observed contour | Timestamped suitable feedback alignment, deviations correlated with geometry/dynamics and inspected outcome |

Current Carvera adapter limits remain explicit. General LinuxCNC transport,
auxiliary axes, mill-turn modes and industrial hardware are not qualified by
mathematical models or a visible UI control. See the other ledgers for shared
prerequisites and their outstanding acceptance gates.
