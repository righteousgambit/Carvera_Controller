# Task and production workflow requirements

These 25 recommendations extend the seven existing ledgers under the active
implementation goal. Reused foundations do not close the complete workflow.
Each requirement remains OPEN until the evidence below is obtained.

| # | Requirement | Required completion evidence |
|---|---|---|
| 1 | Task ribbon | Setup/rehearse/run/inspect use shared scene and preserve unfinished input |
| 2 | Pinned workbench state | Persistent chosen controls/readings share authoritative state without duplicate ownership |
| 3 | Semantic keyboard scrubbing | Native motion/operation/tool-change/contact/retract/inspection navigation |
| 4 | Linked source drawer | Bidirectional source/motion selection, actual interpreter state and ambiguity indications |
| 5 | Problem-focused views | Diagnostic object isolation/framing and accurate previous-view restoration |
| 6 | Actionable alarm cards | Actual alarm/state uncertainty, attached evidence and supported recovery actions |
| 7 | Expandable run status | Compact normal display and useful event-driven diagnostic expansion |
| 8 | Part-linked inspection | Nominal/tolerance/raw results/repeatability/operations with native trends |
| 9 | Interrupted editing restoration | Restart restores context and drafts separately from saved/applied/observed state |
| 10 | Controller rehearsal | Real UI against isolated simulated backend, fault and recovery workflows |
| 11 | Dependency-aware scheduling | Explicit operation prerequisites and reviewed reordered program with verified semantics |
| 12 | Tool-efficient multi-part scheduling | Compared strategies, measured savings and inspection/feature dependencies |
| 13 | Access-aware stock nesting | Clamps, reach, release, webs and applicable grain constraints in generated setup |
| 14 | Part release planning | Support states after operations and exact unsupported transition with reviewed tabs/webs |
| 15 | Sequenced workholding | Separate operation-bound setup states and actual operator reconciliation |
| 16 | Fastener setup instructions | Specified bolt engagement/stacks/sequence/torque linked to exact fixture setup |
| 17 | Rotary balance review | Declared mass/CoG/overhang and actual documented machine applicability |
| 18 | Axis-linked finish map | Geometry/dynamics/process settings tied to inspected surface outcomes |
| 19 | Overlapped ATC preparation | Actual capable backend prepare/prepared/change handshakes and timeline |
| 20 | Sensor disagreement diagnostics | Aligned signals, competing explanations, freshness and qualified interpretation |
| 21 | Effective adaptive feed | Program/operator/adaptive/axis-limited components and verified capable-backend execution |
| 22 | Motion-synchronized outputs | Supported boundary actions and device timing/feedback qualification |
| 23 | External axis corrections | Capable-backend programmed/corrected path, limits, clearance and qualified sensor loop |
| 24 | Triggered diagnostic capture | Bounded pre/post-event buffer with gaps, motion and camera timing |
| 25 | Executable acceptance suites | Configuration-bound repeatable machine tests, receipts and change invalidation |

The LinuxCNC capability declaration currently has no execution transport.
Advanced backend and hardware requirements remain open until physically
qualified; desktop simulation and unit tests are distinct evidence gates.
