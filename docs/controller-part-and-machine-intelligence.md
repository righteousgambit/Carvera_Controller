# Part and machine intelligence workflows

These 25 requirements supplement every earlier controller workflow ledger under
the active implementation objective. All complete workflows remain OPEN. Preview
engines and source tests do not establish backend execution or physical acceptance.

| # | Requirement | Required acceptance evidence |
|---|---|---|
| 1 | Part/setup navigator | Linked part, setup, operation, tool and inspection selection preserves context across native workflows. |
| 2 | Persistent comparison tray | Pinned cutter, holder, fixture and machine alternatives expose geometry, reach, clearance and timing differences. |
| 3 | Named setup branches | Alternatives round trip and compare without overwriting accepted setup or commanding the machine. |
| 4 | Section cuts/isolation | Hidden geometry can be sliced and isolated with recoverable view state and linked clearance issues. |
| 5 | Coordinate breadcrumbs | Machine/plate/vise/jaw/stock/feature transforms retain source and measured versus estimated status. |
| 6 | Teach named positions | Fresh reported positions, camera references and approach descriptions persist; returning is a separately reviewed action. |
| 7 | Consequential-action previews | Proposed offsets, pocket changes and probe actions show effects and obtain applicable backend readback. |
| 8 | Setup-change inbox | Program, geometry, tooling, firmware and measurement changes identify affected derived checks and remedies. |
| 9 | Physical toolroom | Individual cutters, assemblies, storage, quantities, scan identities and pockets remain linked. |
| 10 | Capability activation | Actual availability, missing configuration/measurement/hardware and activation steps are explained per machine. |
| 11 | Postprocessor contracts | Program-bound dialect, compensation, units, topology and post revision compare against actual backend identity. |
| 12 | Backend interpreter simulation | Supported interpreter expansion preserves macros/subprogram/cycle semantics and unresolved regions. |
| 13 | Operation stock checkpoints | Residual stock round trips, resumes and transforms across registered setups. |
| 14 | Fixture accessibility map | Reachability distinguishes cutter/holder obstruction, candidate assemblies and alternate setups. |
| 15 | Deflection/rigidity estimates | Explicit force, assembly and material assumptions expose sensitivity and limitations. |
| 16 | Spindle power/torque envelopes | Machine-specific curves and proposed process demand inform candidate recipes without inventing measured capacity. |
| 17 | Operation-specific adaptation | Roughing/finishing/drilling/threading policies obey supported bounded response and operation identity. |
| 18 | Adaptive response experiments | Measured delay, noise, repeatability and range bind a process signal to the applicable machine and cut. |
| 19 | Controller-local adaptation | Qualified local sampling/action enforces bounds, stale-data handling, acknowledgment and desktop handoff. |
| 20 | Chatter analysis | Optional synchronized sensors and RPM associate diagnostic signatures and reviewed experiments. |
| 21 | Five-axis orientation corridors | Feasible orientation ranges expose holder clearance, calibrated joint margins and smoothing alternatives. |
| 22 | Pivot-error sensitivity | Rotary calibration errors propagate to tip predictions with measured evidence and explicit assumptions. |
| 23 | Accuracy/speed exploration | Backend-specific exact stop/blending/tolerance alternatives expose path deviation and validated timing. |
| 24 | Machine resource scheduling | Spindle/magazine/probe/pallet/robot/zone ownership explains waits and qualified interlocked execution. |
| 25 | Acceptance-part commissioning | Configuration-bound test parts and measurement plans exercise and retain relevant machine acceptance. |

This ledger does not authorize physical execution, machine configuration writes,
automatic adaptive control or publication. Current program dependency inspection
advances setup awareness but does not close any complete requirement above.
