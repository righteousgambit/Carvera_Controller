# Task-centered and executable controller workflows

These additional 25 requirements preserve the full active implementation scope.
They extend overlapping earlier requirements rather than replacing their acceptance
gates. A local engine or declaration does not establish actual execution or physical
qualification. Requirements below remain open until their full end state is proven.

| # | Requirement | Required end state |
|---|---|---|
| 1 | Task-centered workbench | Selection exposes operation/tool/setup/process/inspection context while media panes retain their space. |
| 2 | Pinnable instrument strip | Chosen actual values remain readable across tasks with age and observed source. |
| 3 | Shared entity selection | Scene, source, measurements, tooling and camera preserve linked entity identity. |
| 4 | Dimension-aware inputs | Units and expressions are validated with illustrated definitions and measured/entered/derived distinctions. |
| 5 | Constrained illustrated setup | Fixture-hole and jaw relationships support exact editable placement with measured versus estimated provenance. |
| 6 | Setup-change preview | Combined drafts expose reach, clearance, path and inspection consequences with review and undo. |
| 7 | Rich program browser | Program/setup/tool/outcome previews and CAM revision comparisons retain active-run identity. |
| 8 | Coordinated machining timeline | Actual camera, motion, telemetry and intervention events synchronize with explicit gaps. |
| 9 | Visual problem explanations | Selected issue isolates captured geometry and motion with dimensioned remedy comparisons. |
| 10 | Focused execution layout | Actual operation/tool/progress/exceptions and guided recovery remain clear while preparation drafts persist. |
| 11 | Physical tool passports | Individual assemblies retain CAD, measured geometry, seating, use, recipes and inspection history. |
| 12 | Complete two-bank execution | Reviewed stop, physical loading reconciliation, length measurement and validated resume work end to end. |
| 13 | Predicted-engagement adaptation | Stock engagement predictions and observed process signals inform bounded qualified adaptive execution. |
| 14 | Machine-side adaptive loop | Timing-sensitive capable-backend execution has bounded authority, stale-data behavior and operator handoff. |
| 15 | Process-identification bench | Reviewed experiments retain response delay/noise/load/feed effects for applicable process tuning. |
| 16 | Stock-aware efficiency | Rest material and air-cut candidates compare engagement, time and clearance before reviewed export. |
| 17 | Feature measurement/correction | Nominal/tolerance associations expose cross-feature correction effects with qualified writes and readback. |
| 18 | Offset/compensation trace | Selected motion explains work/local/tool/cutter/rotary transforms and effective pose. |
| 19 | Operation restart planning | Actual interruption state, modal state, tooling, offsets and rest stock produce a reviewed qualified reentry. |
| 20 | Larger magazine tracking | Physical assembly identity remains independent of fixed/random pockets, preselection and sister tools. |
| 21 | Complete rotary setup | Chuck/tailstock/center/travel/winding/feed semantics support indexed, wrapped and simultaneous workflows. |
| 22 | Visible five-axis joints | Alternative solutions, singularities, joint demands and TCP ownership support capable-backend execution. |
| 23 | Synchronized-process workspace | Actual encoder readiness and phase support qualified tapping/threading/gearing; unsupported backends explain alternatives. |
| 24 | Channel/pallet coordination | Machine resources and shared zones explain waits and qualified overlap across channels and pallets. |
| 25 | Executable commissioning | Actual-interface fault simulation and physical machine acceptance retain configuration-bound evidence. |
